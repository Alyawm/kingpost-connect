# Devlog — Code review: security, redundancy and performance (v2.0.1)

Date: 2026-10-26
Scope: the whole repository after Phase 9

## How it was checked

- Dependencies: `pnpm audit` for the JavaScript side; every crate in `Cargo.lock` looked up
  in the OSV advisory database (no Rust audit tool is installed on this machine).
- Code: clippy with the pedantic and nursery groups on top of the usual gate; an in-house
  scan of TypeScript exports nothing references and of Cargo dependencies no source
  mentions; a read of every command the interface can call and every server request, for
  what they accept and where they write.
- Live: the desktop sync panel and the web viewer against a local server, as in the
  Phase 9 devlog.

## Security

- **Links could launch programs.** An element link of kind "file" may point anywhere on
  the disk, and links travel between copies through sync. Opening one handed the path to
  the system, which runs an `.exe`, `.bat`, `.ps1`, `.lnk` and so on. Links to programs
  and scripts are now refused with a message; documents and folders open as before.
- **Save commands wrote wherever the interface said.** Exporting an image, a CSV, a BCF
  file, a schedule or the diagnostics bundle took a path from the interface and wrote
  there. The path still comes from the save dialog, but the shell now checks it: a full
  path, into a folder that exists, with one of the file types the dialog offered. A
  compromised interface could no longer drop a file of its choosing anywhere.
- **Server answers carry browser protections.** `Content-Security-Policy` for the web
  viewer (only the server itself may be loaded, nothing may frame it), `nosniff`,
  `Referrer-Policy` and `X-Frame-Options` on every answer. Sign-in requests are capped at
  16 KB. Two copies uploading the same file at the same moment no longer trip over each
  other's rename.
- **Device ids are checked before they become trigger SQL.** They were always generated
  by the application; a database edited by hand could have carried anything.
- **Dependencies.** `zip` 2 → 9 and `quick-xml` 0.37 → 0.42 (advisories: unsafe
  extraction behaviour, which the application never used, and two denial-of-service
  cases on malicious XML); `vitest` 3 → 4 (test runner only; two critical advisories in
  its worker pool). The updater's own `zip` 4 is the plugin's to update. Two advisories
  remain in the Linux build of Tauri's GTK bindings (`glib`, `proc-macro-error`), both
  transitive and not reachable from this application's code.

## Redundancy

- Four commands the interface never called (`revision_info`, `search_elements`,
  `issue_set_elements`, `viewpoint_delete`) and their wrappers, a store method only they
  used, four unused interface functions, two unused transport accessors, a sync query
  superseded by `changes_to_send`, and two public types of the store that nothing outside
  it used.
- A duplicated hex helper in the desktop commands.

## Performance

- **Applying received changes.** The sync store looked up each table's columns with a
  `PRAGMA` per applied row and compiled its SQL afresh each time. Columns are now read
  once per connection and the statements go through SQLite's prepared-statement cache
  (capacity raised to 128). Applying 7,000 clash rows in one batch (release build, in
  memory) took 950–1,000 ms before and 210–230 ms after; joining the sample project
  applies about that many rows.
- **Server change relay.** Pushed changes were parsed, validated, serialised again and
  stored; pulled changes were parsed and serialised again on the way out. Both now pass
  the stored JSON through as text (still parsed once on the way in, for validation).
- Hex encoding of hashes and tokens builds one string instead of one per byte; the SAF
  reader no longer copies a workbook's bytes before opening it.

## Not changed, by choice

- Clippy's `needless_pass_by_value` on commands (204 hits): Tauri commands take their
  arguments by value; the lint does not apply.
- The localisation scaffold (`setLocale`, `availableLocales`) has no caller yet; it is the
  documented hook for a second language and stays.
- Exported types used only inside their own file: harmless, left alone.
